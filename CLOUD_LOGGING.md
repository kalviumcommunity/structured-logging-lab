# Cloud Logging & Traceability Guide

This document outlines how structured JSON logs generated by `orders-api` map to modern cloud logging platforms and log management services.

---

## 1. Overview & Cloud Log Ingestion

When containerized services emit structured JSON logs to standard output (`stdout`) and standard error (`stderr`), cloud container runtime agents (such as Google Cloud Logging Agent/Fluentbit, AWS CloudWatch Agent, or Promtail for Grafana Loki) automatically parse the JSON output without requiring custom log scrapers or regex parsers.

### Field Mapping Matrix

| App Field | Standard Type | Cloud Log Field Target | Description / Purpose |
| :--- | :--- | :--- | :--- |
| `ts` | ISO 8601 String | `timestamp` | Event timestamp for chronological indexing |
| `level` | String | `severity` / `level` | Severity filter (`info`, `warn`, `error`, `debug`) |
| `service` | String | `labels.service` | Microservice identifier (`orders-api`) |
| `msg` | String | `message` / `jsonPayload.msg` | Human-readable log event description |
| `reqId` | UUID String | `jsonPayload.reqId` / `trace_id` | Correlation ID for end-to-end request tracing |

---

## 2. Searching Logs in Cloud Log Platforms

### Google Cloud Logging (Cloud Operations)

In Google Cloud Logging, JSON log lines automatically populate the `jsonPayload` structure.

**Filter by Error Severity:**
```gcl
resource.type="k8s_container"
jsonPayload.service="orders-api"
severity="ERROR"
```

**Trace Specific Request Journey by `reqId`:**
```gcl
resource.type="k8s_container"
jsonPayload.service="orders-api"
jsonPayload.reqId="a1b2c3d4-e5f6-7890-abcd-ef1234567890"
```

---

### Grafana Loki (LogQL)

Grafana Loki ingests raw lines and parses JSON dynamically using the `json` parser stage.

**Filter All Errors:**
```logql
{app="orders-api"} | json | level="error"
```

**Trace Single Request by Correlation ID:**
```logql
{app="orders-api"} | json | reqId="a1b2c3d4-e5f6-7890-abcd-ef1234567890"
```

---

### Datadog Log Management

Datadog automatically extracts top-level JSON attributes:

```datadog
service:orders-api status:error @reqId:"a1b2c3d4-e5f6-7890-abcd-ef1234567890"
```

## 3. Distributed Tracing & Propagation

- The service generates a unique `reqId` per incoming HTTP request if an `X-Request-ID` header is not present.
- Downstream HTTP requests to other internal microservices (e.g., payment gateways, inventory service) should forward the `X-Request-ID` header.
- This allows a single transaction to be traced end-to-end across multiple microservice log streams.

---

## 4. Security & Data Protection Policy

To comply with security and privacy standards (GDPR, PCI-DSS, SOC 2):

1. **No Sensitive Data Logging**: Never log passwords, access tokens, API keys, session cookies, or full payment details (such as credit card numbers or CVVs).
2. **Use Identifiers Only**: Log resource identifiers (`customer_id`, `order_id`, `reqId`) instead of sensitive payloads.
3. **Log Sanitization**: Any contextual objects passed to logger calls must be audited to ensure sensitive request body fields are scrubbed.
